# Methods review: Li (2021) and Mockert (2023)

Reviewed November 25, 2026 using the author's two uploaded full-text PDFs. Page numbers below are the printed PDF pages (both papers have 14). Also inspected pinned author code and supplementary Figures S1/S2; both were rendered and visually checked. Sources and byte hashes are recorded in [provenance](paper_review_sources.json). The PDFs, extracted text, supplementary PDFs and external source code remain outside Git. No external workflow was executed.

## Recommendation and fixed-layout evidence

Use the **Li-style simultaneous low-resource analysis as the primary reference**, with the **Mockert-style 48-hour combined-energy analysis as a complementary scenario**. Both are already implemented as separately named methods; this review does not change their existing results. Retain observed-generation validation before interpreting long-period event counts. Reproduce stated definitions with explicit California adaptations rather than presenting our pipeline as an exact replication of either European study.

There is direct published support for the author's fixed-layout choice. **Li et al., §2.1, p. 4**, apply 1985–2016 weather to wind/solar farms at their 2016 locations and installed capacities. Holding the reference system constant lets weather vary without confusing that variation with fleet growth or relocation. Our proposed 2020 California reference follows that experimental-design principle; the reference year, geography, asset population and physical conversions differ and must be stated. It estimates the behavior of a reference system under historical weather, not actual generation in each historical year.

North Pacific circulation analysis would need a separate domain, fields and classification. Seasonal controls are useful; our year-block uncertainty approach remains a distinct choice. |

Li's generation forcing is particularly important: the paper's use of ERA5 for meteorological explanation does **not** make its Renewables.ninja CFs ERA5-driven. Its duration-distribution comparison also uses different climatological periods (Ninja 1985–2016 versus TSO 2015–2018). That is not a substitute for our same-period paired validation.

## Author-code audit: published method versus current implementation

Inspected `fmockert/dunkelflauten_DE` at **8f8f5563c4ea40fedbeb85aed8180a0be21ddf40**, rather than relying on mutable main. This is the current archived source inspected for this review, not a verified software environment snapshot from the 2023 publication.

- `make_linear_regression.py` regresses observed CF on modeled CF and applies slope/intercept. Its inspected code does not establish a withheld temporal validation split or bounds handling. The config includes German fallback slopes/intercepts; they must not be used for California when data are missing.
- `build_capacity_factors.py` computes CF-based spatial weights inside its annual loop. This is not evidence for a frozen EIA-asset layout. The inspected source also has unresolved execution issues, including a missing `carrier` assignment, an output-name typo and configuration-key inconsistencies. Its deprecated pandas interfaces require an older environment or adaptation. We did not run it or infer that these current-source issues invalidate the paper's published results.
- `build_dunkelflauten.py` uses a **centered** running mean with `min_periods=0`, index expansion, a fixed 48-step skip, and later rounding to six-hour weather-regime timestamps. Those details differ from our exhaustive union of complete windows and precise UTC intervals. The published §2.4 prose is the basis for our explicitly labeled adaptation; do not claim byte-for-byte catalogue reproduction from this source.
- Centered versus trailing labels alone need not change the physical support of **complete** 48-hour windows. A centered label at index `i` uses observations `i−24 … i+23`, the same window as a trailing endpoint at `i+23`. Our support-union implementation therefore retains the same full-window interpretation while making endpoints explicit. Partial edge windows and rounded/skip-based extraction can change results.

[Independent synthetic support checks](../results/tables/paper_method_support_checks.json) illustrate the distinction. A 72-hour internal CF=0.01 block amid CF=0.5 gives 33 qualifying full windows and an 80-hour support union under either full-window labeling. A 24-hour low block at the left edge gives **zero** qualifying complete windows but **three** low partial-centered windows. These are mathematical controls, not results from executing the external code or observed weather. Exactly 24 low hours also pass our `>=24` rule but fail `>24`.

The source was read for method verification, not copied into the project. Supplement S2 confirms that corrected and uncorrected German CFs were compared; it does not provide a California calibration or show that the current January discrepancies have been resolved.

## What changes next, and what stays provisional

1. **Keep the fixed reference system and separate event families.** Preserve previous outputs. Register the `>24h` compatibility comparison explicitly rather than silently changing the pilot duration. Keep 48-hour incomplete-context flags and include all qualifying-window support.
2. **Test the resource conversions with the required data.** Compare unchanged physics with controlled alternatives for height/roughness, direct/diffuse irradiance, albedo and PV conversion. Preserve realistic EIA capacities/siting and tracker distinctions. A German reference turbine or south-facing panel is a benchmark, not verified California equipment.
3. **Consider calibration only with defensible targets.** The papers support observation-based calibration, not arbitrary January multipliers. The current whole-plant EIA-923 energy comparison and BA-wide hourly shapes have different populations/support. Do not regress one against the other as if matched. Define calibration period, targets, bounds/night behavior and diagnostics; freeze parameters before examining held-out observed energy. Report uncorrected and calibrated versions, errors and uncertainty.
4. **Keep temperature claims specific.** Add paper-inspired anomaly summaries if useful after the full baseline exists. Our percentile/run index remains an explicitly defined extension. Mockert's §3.3 uses 1,000 resamples and season matching within ±45 days for regime life-cycle comparisons, with a specific 20% criterion; it is not a generic 5%-significance test or a prescribed bootstrap for our temperature coincidences.
5. **Acquire a limited dataset first.** The [prepared validation plan](limited_validation_download.md) reuses January's four baseline variables, adds six missing fields, and obtains adjoining February/endpoints. Summer 2020 and observed-energy holdouts in January/July 2021 are separately staged. Existing five-cell January 2021 weather has already been inspected, so only its matched observed-generation evaluation is described as withheld. No parameters have been fitted using it.

New inputs and physical-model comparisons may explain part of the wind/PV discrepancies; that is a hypothesis to test, not a promised correction. The full 2005–2024 acquisition remains unsubmitted. No empirical coefficients, final turbine model, tracker treatment or climatological event frequencies are selected by this literature review.
